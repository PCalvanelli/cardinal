# P002: proof rests on unchecked assumptions

An `exactly_once` contract is proven, but the proof rests on declared facts that nothing
checks when dbt runs. If the data breaks one of them, the model silently stops being
exactly-once, and no build fails.

Cardinal proves facts about models from facts about their inputs. Where it cannot prove a
fact (at sources, seeds and snapshots, or a declared key the SQL does not prove) it takes
the declaration as given. Each such fact is an assumption:

- a key, from `meta.cardinal.grain`, a `primary_key` constraint or a `unique` test;
- a non-null column, from `meta.cardinal.grain`, a constraint or a `not_null` test;
- a reference, from `meta.cardinal.references`.

An assumption counts as checked when a dbt test on the same columns fails the build
(`severity: warn` and tests with a `where` filter do not count), or when an enforced model
contract applies a constraint the warehouse enforces. Constraints on sources are never
applied.

## Fixed

`cardinal assumptions --emit-tests` prints the tests that would check every unchecked
assumption, as YAML to add to your schema files:

```yaml
sources:
  - name: shop
    tables:
      - name: order_items
        columns:
          - name: order_id
            tests:
              - not_null
              - relationships:
                  to: source('shop', 'orders')
                  field: order_id
```

Once dbt runs those tests, static proof and runtime checks together guarantee the
contract: the tests check the sources, and Cardinal proves everything downstream.
