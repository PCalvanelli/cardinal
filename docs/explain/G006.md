# G006: incremental unique_key is not a key

An incremental model sets `unique_key`, but its SQL can produce more than one row per
unique_key in a single run. The merge strategies match each new row to existing rows on
unique_key, so duplicates in the new rows break the merge:

- `merge` fails on Snowflake, BigQuery and Databricks when several new rows match one
  existing row, or updates it from an arbitrary row on warehouses that allow it.
- `delete+insert` deletes the old row and inserts every new one, so the table now holds
  duplicates. A full refresh may not show them, so they can be hard to reproduce.

G006 is reported when the unique_key columns are not a proven key of the model's rows, or
are not in its output at all (an error). It is not reported for `append`,
`insert_overwrite`, `microbatch` or `replace_where`, which do not match on unique_key; for
a unique_key that is an expression rather than columns; when the model's grain is not fully
known; or when a `unique` test on the same columns already reports G002.

## Broken

```sql
{{ config(materialized='incremental', unique_key='order_id') }}

select o.order_id, o.updated_at, p.payment_id, p.amount
from {{ ref('stg_orders') }} o
join {{ ref('stg_payments') }} p using (order_id)   -- several payments per order
{% if is_incremental() %}
where o.updated_at > (select max(updated_at) from {{ this }})
{% endif %}
```

## Fixed

Set unique_key to the grain the SQL produces:

```sql
{{ config(materialized='incremental', unique_key=['order_id', 'payment_id']) }}
```

or reduce the SQL to one row per unique_key:

```sql
select order_id, max(updated_at) as updated_at, sum(amount) as amount
from ...
group by order_id
```
