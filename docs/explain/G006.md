# G006: unique_key isn't unique

Layer: **operator**, each join, filter, aggregate, window and set operation, checked against the keys of what it reads.

An incremental model sets `unique_key`, but its SQL can produce more than one row per
unique_key in a single run. The merge strategies match each new row to existing rows on
unique_key, so duplicates in the new rows break the merge:

- `merge` fails on Snowflake, BigQuery and Databricks when several new rows match one
  existing row, or updates it from a random one of them on warehouses that allow it.
- `delete+insert` deletes the old row and inserts every new one, so the table now holds
  duplicates. A full refresh may not show them, so they can be hard to reproduce.

A snapshot merges the same way on every run. There it is worse: a snapshot's table is
history, and once the source has moved on, versions written wrong can't be rebuilt. Two
rows with the same unique_key in one run make the merge fail, or record two current
versions of one row.

G006 is reported when the SQL doesn't guarantee one row per unique_key, or when the
unique_key columns aren't in the model's output at all (an error). It is not reported for `append`,
`insert_overwrite`, `microbatch` or `replace_where`, which do not match on unique_key; for
a unique_key that is an expression rather than columns; when the model's key isn't fully
known; or when a `unique` test on the same columns already reports G002.

## Broken

```sql
{{ config(materialized='incremental', unique_key='order_id') }}

select o.order_id, o.updated_at, p.payment_id, p.amount
from {{ ref('stg_orders') }} o
join {{ ref('stg_payments') }} p using (order_id)   -- several payments per order
{% if is_incremental() %}
where o.updated_at > (select max(updated_at) from {{ this }})
{% endif %}
```

## Fixed

Set unique_key to the key the SQL guarantees:

```sql
{{ config(materialized='incremental', unique_key=['order_id', 'payment_id']) }}
```

or reduce the SQL to one row per unique_key:

```sql
select order_id, max(updated_at) as updated_at, sum(amount) as amount
from ...
group by order_id
```

## Snapshots

```sql
{% snapshot customers_snapshot %}
{{ config(unique_key='customer_id', strategy='timestamp', updated_at='updated_at') }}
select c.customer_id, c.name, a.city, c.updated_at
from {{ source('crm', 'customers') }} c
join {{ source('crm', 'addresses') }} a using (customer_id)   -- several per customer
{% endsnapshot %}
```

Keep one row per customer_id, for example the current address only, or set
`unique_key` to the columns the SQL is unique on.
