# G002: declared key isn't guaranteed by the SQL

Layer: **operator**, each join, filter, aggregate, window and set operation, checked against the keys of what it reads.

A model declares a key through a `unique` or `unique_combination_of_columns` test,
`meta.cardinal.grain`, or a `primary_key` contract constraint, but its SQL doesn't
guarantee one row per key. Only the dbt test checks it: if the test doesn't run, or runs
after downstream models are built, duplicates go unnoticed.

Cardinal still uses the declared key for downstream models, because the test enforces it
at run time. G002 isn't reported for models whose key is unknown because of something
upstream; G004 reports that cause once instead.

## Broken

```yaml
models:
  - name: customer_latest_order
    columns:
      - name: customer_id
        tests: [unique]
```

```sql
select customer_id, order_id, order_date
from {{ ref('orders') }}            -- many orders per customer
where status = 'complete'
```

## Fixed

Make the SQL return one row per key:

```sql
select customer_id, order_id, order_date
from {{ ref('orders') }}
where status = 'complete'
qualify row_number() over (partition by customer_id order by order_date desc, order_id desc) = 1
```
