# G004: key is unknown

Layer: **node**, each model's declared shape: columns, types and grain.

Cardinal couldn't work out a key (what one row stands for) for one or more models, so it
can't check them. It reports each cause once, with the models it affects. Common causes:

- a source or seed with no known key (no `unique` test, no `meta.cardinal.grain`);
- SQL that loses track of the key, such as `UNION ALL` without a column telling the
  branches apart, `UNNEST`, or `GROUPING SETS`;
- an upstream model Cardinal couldn't read (see its E-code);
- a Python model.

Cardinal reports nothing else for these models rather than guess. `cardinal coverage`
ranks the causes by how many models each would unlock, and `cardinal guess` can propose
keys for dbt to test.

## Broken

```yaml
sources:
  - name: shop
    tables:
      - name: order_items     # no key declared
```

## Fixed

```yaml
sources:
  - name: shop
    tables:
      - name: order_items
        meta:
          cardinal:
            grain: [order_id, line_id]
```
