# P001: exactly_once contract isn't proven

Layer: **operator**, each join, filter, aggregate, window and set operation, checked against the keys of what it reads.

A model declares `meta.cardinal.exactly_once: <relation>`, claiming it contains each row
of that relation exactly once, and Cardinal can't prove it. Like a type checker, Cardinal
treats a contract it can't prove as a failure.

"Exactly once" has two halves, and the finding says which one is not proven:

- **at least once**: no row is lost. Filters, `LIMIT`, anti joins and inner joins can drop
  rows. An inner join keeps every row of one side only when every row has a match: its
  join columns are non-null, and the other side contains every value they can take.
  Cardinal knows the second part from a declared reference (`meta.cardinal.references`),
  when the other side keeps every row of the referenced table.
- **at most once**: no row is repeated. The model must still have one row per value of
  the relation's key; a one-to-many join breaks this.

Both halves need the relation's key to tell its rows apart, so the key must be known and
non-null. When the model aggregates and its output no longer has the key, the contract is
checked on the rows the aggregate reads: every row is aggregated exactly once.

dbt `relationships` tests never count as a declared reference. They check a declared one
at run time, which `cardinal assumptions` reports.

## Broken

```yaml
models:
  - name: orders_enriched
    meta:
      cardinal:
        exactly_once: stg_orders
```

```sql
select o.order_id, c.region
from {{ ref('stg_orders') }} o
join {{ ref('stg_customers') }} c on o.customer_id = c.customer_id   -- may drop orders
```

## Fixed

Keep orders without a customer:

```sql
left join {{ ref('stg_customers') }} c on o.customer_id = c.customer_id
```

or declare the reference that guarantees a match, on the source the orders come from:

```yaml
sources:
  - name: shop
    tables:
      - name: orders
        columns:
          - name: customer_id
            tests: [not_null]
            meta:
              cardinal:
                references: shop.customers
```

If the model is meant to drop rows (a filter on status, say), it does not contain every
row of the relation: remove the relation from `exactly_once`.
