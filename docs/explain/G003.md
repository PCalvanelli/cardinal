# G003: many-to-many join

Neither side's join columns are a key of that side, so each matching pair of rows
becomes an output row. Row counts multiply, and every downstream aggregate inherits the
duplication.

Joins with no equality columns (cross joins, pure range joins) are not reported: they
are usually deliberate, such as a date spine crossed with customers.

## Broken

```sql
select o.order_id, p.promo_code
from {{ ref('orders') }} o
join {{ ref('customer_promos') }} p   -- many promos per customer
  on o.customer_id = p.customer_id    -- many orders per customer
```

## Fixed

Reduce one side to one row per join key first, or join on its full key:

```sql
with latest_promo as (
    select customer_id, promo_code
    from {{ ref('customer_promos') }}
    qualify row_number() over (partition by customer_id order by granted_at desc) = 1
)
select o.order_id, p.promo_code
from {{ ref('orders') }} o
join latest_promo p on o.customer_id = p.customer_id
```
