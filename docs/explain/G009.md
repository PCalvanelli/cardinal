# G009: adds amounts in different units

Layer: **operator**, each join, filter, aggregate, window and set operation, checked against the keys of what it reads.

A `sum`, `avg`, `min` or `max` adds amounts in different units into one number, like
adding dollars to yen. A payments table with an `amount` and a `currency` column holds
amounts in many currencies. Summing `amount` per day without grouping by `currency`
mixes them.

Cardinal can't know an amount's unit from the SQL, so this check needs one declaration:
the column that holds each amount's unit.

```yaml
sources:
  - name: app
    tables:
      - name: payments
        columns:
          - name: amount
            meta:
              cardinal:
                unit: currency    # the column holding amount's unit
```

G009 fires at an aggregate of the amount when one group can hold rows with different
units: the GROUP BY (or window PARTITION BY) doesn't include the unit column or something
that fixes it (like `account_id`, when each account has one currency), and no filter
keeps a single unit. It follows the
amount through every model. If a model keeps `amount` but drops `currency`, the units
are unknown from then on, and any later aggregate of it is flagged.

Not flagged: grouping by the unit column, or by a key that determines it (each
`account_id` has one currency); filtering to one unit (`where currency = 'USD'`); and
converted amounts such as `amount * fx.rate`, which are new values.

The default severity is error, since the finding rests on your own declaration.

## Broken

```sql
select order_date, sum(amount) as revenue   -- USD and EUR added together
from {{ source('app', 'payments') }}
group by order_date
```

## Fixed

Group by the unit:

```sql
select order_date, currency, sum(amount) as revenue
from {{ source('app', 'payments') }}
group by order_date, currency
```

Or filter to one unit:

```sql
select order_date, sum(amount) as revenue_usd
from {{ source('app', 'payments') }}
where currency = 'USD'
group by order_date
```

Or convert first:

```sql
select p.order_date, sum(p.amount * fx.rate_to_usd) as revenue_usd
from {{ source('app', 'payments') }} p
join {{ ref('fx_rates') }} fx on fx.currency = p.currency and fx.day = p.order_date
group by p.order_date
```

If every row really has one unit, filter to it or suppress the finding with a reason:

```sql
sum(amount) as revenue  -- cardinal: allow(G009) reason: this store only sells in USD
```
