# G012: UNION merges rows that can repeat

Layer: **operator**, each join, filter, aggregate, window and set operation, checked against the keys of what it reads.

`UNION` (without `ALL`) removes duplicate rows from its result. When a branch can
return the same row twice for two different underlying rows, the de-duplication merges
them into one, and a real row disappears: two payments of 10.00 by the same customer
become one payment.

G012 is reported when a branch's key is known to be gone (it selects columns that leave
out the key of what it reads, so two of its rows can be equal), and the branch returns a
quantity: an aggregate's result, a column declared with `meta.cardinal.measure` or
`meta.cardinal.unit`, or a decimal or floating-point column. A `UNION` of identifiers,
such as `select customer_id from a union select customer_id from b`, is a deliberate
de-duplication and is not reported. Neither is a `UNION` whose rows are already
distinct, for example because every branch keeps its key and a constant column tells the
branches apart.

## Broken

```sql
select customer_id, amount from {{ ref('stg_payments') }}
union
select customer_id, -amount from {{ ref('stg_refunds') }}
```

## Fixed

```sql
select customer_id, amount from {{ ref('stg_payments') }}
union all
select customer_id, -amount from {{ ref('stg_refunds') }}
```

or keep each row's key, so equal amounts stay apart:

```sql
select 'payment' as kind, payment_id as id, customer_id, amount from {{ ref('stg_payments') }}
union all
select 'refund', refund_id, customer_id, -amount from {{ ref('stg_refunds') }}
```
