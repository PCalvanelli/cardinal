# G007: window ordering can tie

A window function whose result depends on row order (`row_number`, `lag`, `lead`,
`first_value`, `last_value`, `nth_value`) is ordered by columns that several rows in a
partition can share. Rows that tie come out in any order, and the warehouse can pick a
different order on every run.

This most often breaks a dedup: `qualify row_number() over (partition by customer_id order
by order_date desc) = 1` keeps a random order when a customer has two orders on the
same date. The model runs, its tests pass, and its values change between runs with no
change to the data.

Only plain columns count as tie-breakers: `order by date_trunc('day', updated_at)` can tie
where `updated_at` does not. first_value, last_value and nth_value are not reported when
every tied row holds the same value. G007 isn't reported when the window's input has an
unknown key.

## Broken

```sql
select *
from {{ ref('orders') }}                  -- one row per order_id
qualify row_number() over (
    partition by customer_id
    order by order_date desc
) = 1
```

## Fixed

Add a tie-breaker, so no two rows in a partition tie:

```sql
select *
from {{ ref('orders') }}
qualify row_number() over (
    partition by customer_id
    order by order_date desc, order_id desc
) = 1
```
