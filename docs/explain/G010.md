# G010: set operation matches columns by position, not name

Layer: **operator**, each join, filter, aggregate, window and set operation, checked against the keys of what it reads.

`UNION` and `UNION ALL` match columns by position. The result takes its column names
from the first branch, so a later branch that lists the same columns in a different
order puts its values under the wrong names, and nothing fails: the types often match.

- **Error**: a later branch's column has the name of a *different* column of the first
  branch. The columns are swapped.
- **Warning**: a later branch's column has a name the first branch doesn't use, so it's
  matched by position only. Alias it to the first branch's name to show it's meant.

Unaliased expressions, such as a literal `'web'`, are not reported: they have no name
of their own.

## Broken

```sql
select customer_id, name, region from {{ ref('customers') }}
union all
select lead_id, region, name from {{ ref('leads') }}    -- region and name swapped
```

## Fixed

```sql
select customer_id, name, region from {{ ref('customers') }}
union all
select lead_id as customer_id, name, region from {{ ref('leads') }}
```

`dbt_utils.union_relations` aligns columns by name for you.
