# P003: guarantee from main is lost

Layer: **operator**, each join, filter, aggregate, window and set operation, checked against the keys of what it reads.

On main, Cardinal proves something about a model, and on this branch it can't. It finds
these by analyzing the base branch's dbt artifacts too, which you pass with `--state DIR`
(or the `DBT_STATE` variable): the same directory dbt's `state:modified` reads. Every
guarantee main proves becomes a check on the branch, without declaring anything.

Cardinal compares two kinds of guarantee:

- **Rows**: the model keeps each row of a parent exactly once. This has two halves, and
  the finding says which one is lost. **At least once** means no filter, `LIMIT` or join
  drops a row. **At most once** means no join repeats a row. Cardinal checks this for
  every parent with a known key.
- **Key**: the model has one row per key, such as one row per `order_id`.

P003 reports a guarantee only when main proves it and Cardinal can name what broke it: a
join that repeats rows, a join or filter that may drop them, or columns that are no longer
unique. If Cardinal can't tell, it says nothing. One change can break guarantees in many
models downstream, so P003 reports each cause once and lists the other models it affects.

A lost guarantee is an error, with one exception: rows dropped only by a `WHERE` filter
are a warning, since someone wrote that filter on purpose.

Findings that main already has are not new, so `--state` doesn't report them or fail on
them. The summary says how many it hid.

## Broken

On main, `orders_enriched` has one row per order:

```sql
select o.order_id, o.status, c.name as customer_name
from {{ ref('stg_orders') }} o
left join {{ ref('stg_customers') }} c on o.customer_id = c.customer_id
```

The branch adds payments:

```sql
select o.order_id, o.status, c.name as customer_name, p.amount
from {{ ref('stg_orders') }} o
left join {{ ref('stg_customers') }} c on o.customer_id = c.customer_id
left join {{ ref('stg_payments') }} p on o.order_id = p.order_id   -- one row per payment
```

An order with two payments now appears twice, so a sum over the model counts it twice.

## Fixed

Reduce payments to one row per order before the join:

```sql
left join (
    select order_id, sum(amount) as amount
    from {{ ref('stg_payments') }}
    group by order_id
) p on o.order_id = p.order_id
```

If the change is intended, say so on the line the finding points at:

```sql
left join {{ ref('stg_payments') }} p on o.order_id = p.order_id  -- cardinal: allow(P003) reason: one row per payment from now on
```

A finding about a whole model, with no line, takes the comment anywhere in the model's
file. Once the branch is merged, main no longer has the guarantee, so the comment matches
nothing. Cardinal doesn't report an unused `allow(P003)` as G005; remove it whenever you
like.
