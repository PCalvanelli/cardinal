# E006: unresolved column

Layer: **node**, each model's declared shape: columns, types and grain.

The compiled SQL reads a column that is not among the upstream relation's known
columns, so Cardinal can't type the model. It is not checked by the operator layer, and
its dependents see an unknown input (reported once as G004).

Columns of models come from their analyzed SQL. Columns of sources come from
`target/catalog.json` (`dbt docs generate`) or from `columns:` in the source's YAML.
Without either, Cardinal can't plan models that name the source's columns.

## Broken

```yaml
sources:
  - name: shop
    tables:
      - name: orders     # no catalog entry and no columns listed
```

## Fixed

```sh
dbt docs generate
```

or list the columns:

```yaml
      - name: orders
        columns:
          - name: order_id
            data_type: integer
```
