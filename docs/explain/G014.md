# G014: deleted rows kept: soft-delete flag dropped without a filter

Layer: **operator**, each join, filter, aggregate, window and set operation, checked against the keys of what it reads.

Sync tools often don't delete a row that was deleted at the source. They keep it and set
a flag: `_fivetran_deleted` (Fivetran, true when deleted), `_sdc_deleted_at`
(Stitch), `_ab_cdc_deleted_at` (Airbyte CDC). Until a model filters on the flag,
deleted rows count like live ones: deleted orders still add to revenue.

Cardinal follows each flag from the source through the models that read it. A model
may keep the flag in its output for a later model to filter, so carrying it is fine.
G014 is reported once, on the model that stops carrying it when nothing on the way
read it in a `WHERE`, join condition or aggregate: after that point, nothing
downstream can tell deleted rows apart.

If a model keeps deleted rows on purpose, such as an audit table, say so with
`-- cardinal: allow(G014) reason: ...`.

## Broken

```sql
-- stg_orders.sql
select order_id, customer_id, amount
from {{ source('shop', 'orders') }}
```

## Fixed

```sql
select order_id, customer_id, amount
from {{ source('shop', 'orders') }}
where not coalesce(_fivetran_deleted, false)
```

or keep the flag so the models after it can decide:

```sql
select order_id, customer_id, amount, _fivetran_deleted
from {{ source('shop', 'orders') }}
```
