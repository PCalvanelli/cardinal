# D001: declaration doesn't match the model

Layer: **node**, each model's declared shape: columns, types and grain.

A `meta.cardinal` setting names a column the relation doesn't have, or isn't written in
a form Cardinal reads. Cardinal ignores the setting, so nothing that depends on it is
checked: a `grain` on a missing column declares no key, and a `measure` or `unit` on one
protects no sum.

Cardinal compares the names with the model's output columns when it can read the
model's SQL, and otherwise with `target/catalog.json` or the columns listed in YAML. If
you just added the column, run `dbt docs generate` so the catalog has it.

This check needs no SQL, so `cardinal check --layer graph,node` runs it on the output of
`dbt parse`.

## Broken

```yaml
models:
  - name: orders
    meta:
      cardinal:
        grain: [order_key]          # the model's column is order_id
    columns:
      - name: amount
        meta:
          cardinal:
            unit: currency_code     # the model's column is currency
```

## Fixed

```yaml
models:
  - name: orders
    meta:
      cardinal:
        grain: [order_id]
    columns:
      - name: amount
        meta:
          cardinal:
            unit: currency
```
