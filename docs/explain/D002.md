# D002: declaration names the wrong relation

Layer: **graph**, every ref() and declared relation resolves.

A `meta.cardinal` setting names a relation that isn't in the project, or one the model
doesn't read:

- `references` names something that is not a model, seed, snapshot or source. Cardinal
  ignores the reference, so inner joins that rely on it are treated as joins that may
  drop rows. This is a warning.
- `exactly_once` names something that is not a model, seed, snapshot or source, or a
  relation that isn't upstream of the model. A model can't keep every row of a
  relation it never reads, so the contract can't hold. This is an error.

This check needs no SQL, so `cardinal check --layer graph,node` runs it on the output of
`dbt parse`.

## Broken

```yaml
models:
  - name: order_lines
    meta:
      cardinal:
        exactly_once: order_items     # the staging model is stg_order_items
    columns:
      - name: customer_id
        meta:
          cardinal:
            references: customer      # the model is customers
```

## Fixed

```yaml
models:
  - name: order_lines
    meta:
      cardinal:
        exactly_once: stg_order_items
    columns:
      - name: customer_id
        meta:
          cardinal:
            references: customers
```

For a source, write `source_name.table_name`.
