# G008: adds up a number that can't be added

Layer: **operator**, each join, filter, aggregate, window and set operation, checked against the keys of what it reads.

A `sum` adds up numbers that don't add. Some numbers mean something only for the rows
they were computed over:

- **Distinct counts.** `count(distinct user_id)` per day counts each user once per day.
  Summing daily counts per month counts a user once for every day they were active.
- **Averages, ratios and percentiles.** `avg(amount)`, `sum(a) / sum(b)`, `median(x)`.
  Adding two averages, or two conversion rates, gives a number that grows with the
  number of groups and means nothing.
- **Balances and running totals.** A balance per `snapshot_date`, or
  `sum(x) over (order by order_date)`. Each row already includes what came before it, so
  adding rows from different dates counts the same amount again.

Cardinal spots these in the SQL with no setup. A balance, inventory level or other
stock that a source table already holds needs a declaration:

```yaml
sources:
  - name: bank
    tables:
      - name: balances
        columns:
          - name: balance
            meta:
              cardinal:
                measure: {kind: stock, over: [snapshot_date]}   # or {kind: non_additive}
```

`kind: additive` on a model column tells Cardinal that a column it inferred as one of
these can be added after all.

## When it fires

At a `sum` of such a column, when one group of the sum can hold more than one of the
values being added:

- **Average, ratio, percentile, declared non-additive:** a group holds more than one
  input row.
- **Distinct count:** a group can hold two counts that may include the same value.
  `count(distinct order_id)` per day summed per month is exact, because each order has
  one order date.
- **Balance or running total over a date:** a group can hold rows from different dates.
  Grouping by that date, or filtering to one, is fine.
- **`avg` of an average:** a group holds more than one average, and averaging them
  ignores how many rows each covers.

Not flagged: `avg`, `min` and `max` of distinct counts and of balances (the average
balance over a month is a real number). Division of row-level columns, such as
`amount / fx_rate` or `cents / 100`, is a conversion, not a ratio: Cardinal treats a
division as a ratio only when both sides are sums, counts or averages. Cardinal only
judges averages, ratios and distinct counts when it knows the key of the sum's input. A
union or a computed expression (`balance * 2`) drops what Cardinal knows about a column.

Only plain columns in the GROUP BY count. `group by date_trunc('month', day)` puts many
days in one group.

## Broken

```sql
-- customer_aov: one row per customer
select customer_id, avg(amount) as avg_order_value
from {{ ref('stg_orders') }}
group by customer_id
```

```sql
-- region_aov
select c.region,
       sum(a.avg_order_value) as avg_order_value   -- adds up averages
from {{ ref('customer_aov') }} a
join {{ ref('stg_customers') }} c using (customer_id)
group by c.region
```

```sql
-- monthly_active_users
select date_trunc('month', event_date) as month,
       sum(active_users) as monthly_active_users   -- a user active on 3 days counts 3 times
from {{ ref('daily_active_users') }}
group by 1
```

## Fixed

Compute the number again from the rows it summarizes:

```sql
select c.region, sum(o.amount) / count(*) as avg_order_value
from {{ ref('stg_orders') }} o
join {{ ref('stg_customers') }} c using (customer_id)
group by c.region
```

```sql
select date_trunc('month', event_date) as month,
       count(distinct user_id) as monthly_active_users
from {{ ref('stg_events') }}
group by 1
```

For a ratio, sum the numerator and the denominator separately, then divide. For a
balance, group by the snapshot date or keep the latest one per group.

A rolling average written as `sum(active_users) over (rows 6 preceding) / 7` is also
flagged. Write it as `avg(active_users) over (rows 6 preceding)`.

If the sum is intended, for example user-days rather than users, suppress it with a
reason:

```sql
sum(active_users) as user_days  -- cardinal: allow(G008) reason: user-days, not users
```
