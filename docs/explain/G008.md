# G008: distinct count is summed

A `sum` adds up counts of distinct values that can overlap. `count(distinct user_id)` per
day counts each user once per day. Summing those daily counts per month, or as a running
total, counts a user once for every day they were active, not once.

Cardinal records each `count(distinct x)` (also `approx_count_distinct`, `approx_distinct`
and `hll`) with the group-by columns that `x` determines. Two groups can count the same
value only if they differ on the other group-by columns. At a later `sum` of that column
with GROUP BY columns `G`, Cardinal fires G008 when the determined columns plus `G` are not
a key of the sum's input, so one sum group can hold two counts of the same value.

Not flagged: a sum where each counted value belongs to one group. `count(distinct
order_id)` per day summed per month is exact, because each order has one order date.
`avg`, `min` and `max` of distinct counts are not sums and are not flagged. Cardinal
only judges inputs whose grain is fully known. It only follows distinct counts of a
plain column or of `case when … then column end`.

Only plain columns in the sum's GROUP BY count toward the key. `group by
date_trunc('month', day)` puts many days in one group.

## Broken

```sql
-- daily_active_users: one row per event_date
select event_date, count(distinct user_id) as active_users
from {{ ref('stg_events') }}
group by event_date
```

```sql
-- monthly_active_users
select date_trunc('month', event_date) as month,
       sum(active_users) as monthly_active_users   -- a user active on 3 days counts 3 times
from {{ ref('daily_active_users') }}
group by 1
```

## Fixed

Count distinct users per month from the event rows:

```sql
select date_trunc('month', event_date) as month,
       count(distinct user_id) as monthly_active_users
from {{ ref('stg_events') }}
group by 1
```

The same goes for running totals: `sum(active_users) over (order by event_date)` counts
returning users again on every day. Count each user from their first active day
instead.

A rolling average written as `sum(active_users) over (rows 6 preceding) / 7` is also
flagged. Write it as `avg(active_users) over (rows 6 preceding)`.

If the sum is intended, for example user-days rather than users, suppress it with a
reason:

```sql
sum(active_users) as user_days  -- cardinal: allow(G008) reason: user-days, not users
```
