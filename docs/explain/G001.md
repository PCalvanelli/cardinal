# G001: aggregation fans out

An aggregate such as `sum(c)` counts `c` more than once because the rows it reads
repeat `c`. This usually happens after a join: a value that belongs to one entity (an
order's shipping fee) is copied onto every row of a finer entity (each line item), and
summing it per day or per customer counts it once per line.

Cardinal fires G001 when, for an aggregate over column `c` with GROUP BY columns `G`, some
entity `D` that determines `c` (its *native grain*) has `D ∪ G` that is not a key of the
aggregate's input. Then two input rows can share `D`, and with it the same `c`, inside
one group.

Exempt: `min`, `max`, `any_value`, `bool_and`, `bool_or`, `count(*)`, `count(distinct …)`,
and arguments with no column references such as `sum(1)`. Aggregates Cardinal does not
know are reported at warning severity.

## Broken

```sql
-- order_lines: one row per (order_id, line_id), joined from orders
select
    order_date,
    sum(line_amount) + sum(shipping_fee) as revenue   -- shipping_fee repeats per line
from {{ ref('order_lines') }}
group by order_date
```

## Fixed

Aggregate the order-level value at order grain first:

```sql
with orders as (
    select order_id, order_date, any_value(shipping_fee) as shipping_fee, sum(line_amount) as lines
    from {{ ref('order_lines') }}
    group by order_id, order_date
)
select order_date, sum(lines) + sum(shipping_fee) as revenue
from orders
group by order_date
```

Or read `shipping_fee` from the relation at its own grain (`shop.orders`).

If the repetition is intended (the value was allocated per line upstream), suppress it
with a reason:

```sql
sum(shipping_fee) as shipping  -- cardinal: allow(G001) reason: fee is allocated per line upstream
```
